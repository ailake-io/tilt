# Benchmarks publicados da beta

Os números abaixo são uma referência inicial para `v0.2.0-beta.1`. Foram
medidos em CPU, com 2 milhões de linhas e o mesmo workload de agrupar, filtrar
e fazer join. Cada backend foi executado no mesmo host; o caminho RPC do Tilt
representa o uso recomendado para separar o processo cliente do executor.

| Backend | Agrupar (ms) | Filtrar (ms) | Join (ms) |
|---|---:|---:|---:|
| Tilt RPC — referência | 169,026 | 174,722 | 385,664 |
| pandas | 406,002 | 395,237 | 543,041 |
| Polars | 62,583 | 52,801 | 58,563 |
| DuckDB | 112,663 | 101,145 | 96,519 |

O Tilt já fica à frente do pandas nesses três cenários, mas Polars e DuckDB
continuam mais rápidos em cargas grandes. Os ganhos recentes de seleção tardia,
spill de agregação e dictionary encoding reduzem custo e RSS, porém ainda não
fecham a diferença para esses motores especializados. Não use estes números
para escolher um backend sem repetir o teste com o seu schema, cardinalidade,
disco e número de threads.

## Reproduzir

```bash
python3 scripts/benchmark_data_backends.py build/release/bin/tilt \
  --rows 2000000 --repetitions 3
```

Se pandas, Polars ou DuckDB não estiverem instalados, crie um ambiente isolado:

```bash
python3 -m venv /tmp/tilt-bench
. /tmp/tilt-bench/bin/activate
python -m pip install -U pip pandas polars duckdb pyarrow
python3 scripts/benchmark_data_backends.py build/release/bin/tilt \
  --rows 2000000 --repetitions 3
```

Para cargas de 10M/100M, use `--rows` e registre CPU, RAM, versão dos pacotes,
codec Parquet e número de threads. Os arquivos brutos e as limitações do
benchmark estão em [`roadmap-performance.md`](roadmap-performance.md) e
[`data-backends-2026-09-30-2m.md`](data-backends-2026-09-30-2m.md).
